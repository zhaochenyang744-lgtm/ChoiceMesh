# ChoiceMesh 版本规划

| 字段 | 内容 |
|---|---|
| 文档版本 | V1.0 |
| 更新日期 | 2026-07-28 |
| 当前状态 | 规划中 |

## 1. 版本原则

- 每个版本只验证一个主要风险；
- 先建立纵向闭环，再提高视觉完成度；
- 没有固定评测结果，不升级 AI 版本；
- 未通过阶段门槛的功能不进入下一个版本；
- 版本号表示产品成熟度，不代表用户价值已经得到验证。

## 2. 版本路线

### V0.1：Decision Core

目标：证明约束模型和排序规则可以确定性运行。

范围：

- 房间、成员、候选和偏好 JSON Schema；
- 硬性约束过滤；
- 软性偏好评分；
- 无解识别；
- 20–40 个固定样例；
- 命令行或测试输出。

不包含 UI 和 AI。

进入下一版门槛：

- 硬性过滤、无解识别和稳定性测试 100% 通过。

### V0.2：Room Flow

目标：证明多成员可以完成结构化共同决策。

范围：

- 创建房间；
- 添加候选；
- 邀请成员；
- 结构化偏好表单；
- 推荐和无解页面；
- 最终确认。

暂不包含自然语言输入和 AI 解释。

进入下一版门槛：

- 三个独立成员完成完整流程；
- 无跨房间数据访问；
- 推荐和确认状态不会混淆。

### V0.3：AI Assist

目标：验证 AI 是否在不控制决定的前提下降低输入和理解成本。

范围：

- 自然语言结构化；
- 澄清问题；
- 取舍解释；
- 一致性校验；
- 模板降级；
- AI 离线评测集。

进入下一版门槛：

- 达到结构化和解释评测阈值；
- S0/S1 错误清零；
- 模型失败不影响规则结果。

### V0.4：Feedback Loop

目标：完成推荐—反馈—一次修订—确认的闭环。

范围：

- 成员反馈；
- 反馈总结；
- 一次修订；
- 前后版本对比；
- 最终行动摘要；
- 基础事件记录。

进入下一版门槛：

- 所有状态转换可测试；
- 反对意见不被遗漏；
- 修订后仍无解时能正确结束。

### V0.5：Validated Beta

目标：通过小规模真实任务验证可用性和价值。

范围：

- 2–3 个小组测试；
- 与群聊或投票基线比较；
- 修复高优先级问题；
- 记录质量、延迟和成本；
- 完善隐私说明和数据删除。

进入下一版门槛：

- 用户结果达到最低目标；
- 无 S0/S1 问题；
- 核心任务移动端可完成。

### V1.0：Public Portfolio Release

目标：公开演示并形成求职材料。

范围：

- 可访问 Demo；
- 可复现 GitHub 仓库；
- 合成演示数据；
- 架构与评测说明；
- 已知限制；
- Case Study；
- 简历项目描述；
- 演示视频或 GIF。

## 3. 后续可能方向

仅在 V1.0 后、且有证据支持时考虑：

- 自动发现候选地点；
- 日历导出或授权后读取可用时间；
- 多轮协商；
- 周期性群体活动；
- 决策模板；
- 不同公平策略；
- 更大群体；
- 团队工作决策。

这些方向不属于当前承诺。
