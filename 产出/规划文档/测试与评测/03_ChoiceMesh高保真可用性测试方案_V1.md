# ChoiceMesh 高保真可用性测试方案 V1

| 字段 | 内容 |
|---|---|
| 原型 | `产出/交付物/产品原型/06_ChoiceMesh_高保真原型_V3/index.html` |
| 状态 | 已结束；探索性样本，详见 `产出/规划文档/用户研究/13_ChoiceMesh高保真可用性测试综合_V1.md` |
| 原计划样本 | 5 位新参与者；另设 1 位备选 |
| 实际样本 | 2 位文字过程记录；其中 HF-01 的手机部分为响应式代码推断，HF-02 为文字反馈 |
| 时长 | 每场 30 分钟，预留 5 分钟收尾 |
| 形式 | 单人远程或当面；任务执行、思考出声、简短回访 |
| 设备 | 3 位手机宽度、2 位桌面宽度；每位只使用一种指定设备 |

## 1. 目的

确认高保真版本没有因视觉、响应式和信息密度变化引入新的理解或操作问题，并验证以下关键机制在界面中仍然成立：

1. 用户能区分“轮到我处理”“需要其他成员处理”与“仅供知情的风险”。
2. 用户能在手机端发现并使用导航抽屉，不会把它误认为永久侧边栏或遗漏入口。
3. 用户能读懂候选覆盖表中的 C / A / B 列，并找到下一步。
4. 用户理解私人条件只能由本人更新，提醒不会替对方提交。
5. 用户能完成暂定、明确发布、查看已发布版本，以及发布后提出问题的闭环。
6. Toast、弹窗、抽屉和状态提示不会遮挡或打断关键操作。

本轮不验证真实服务端权限、真实身份认证、邀请链接安全性、路线计算准确性或 AI 解析质量。

## 2. 参与者

- 最近 3 个月内至少参与过一次 3–6 人朋友、同学或同事活动协调；
- 至少 2 人曾创建或组织过活动；
- 不招募参与过 ChoiceMesh 低保真或中保真测试的人；
- 可使用英文界面完成基础阅读；不要求提供真实预算、路线、联系人或私人原因；
- 默认不录音。若需要屏幕录制或录音，开始前单独取得同意。

## 3. 测试前设置

1. 使用 V3 原型，浏览器缩放 100%。
2. 手机组使用 390–430px 宽度；桌面组使用至少 1280px 宽度。
3. 每场从 `index.html?scenario=collaboration&test=1` 打开，使参与者直接进入既有协作状态，而非创建房间。
4. 主持人仅在需要推进情境时使用快捷键：`Alt+1` 模拟一位成员本人提交反馈；`Alt+2` 模拟另一位成员同意按最低人数继续；`Alt+0` 重置当前情境。参与者界面不显示测试控制。
5. 记录表与每位参与者的原始记录保存在 `参考资料/用户研究原始材料/08_高保真可用性测试/记录/`。

## 4. 统一情境

你正和三位朋友安排周末活动。当前有三个候选：城市散步与午餐、交通枢纽附近活动、公园野餐。一位成员还没提交第一条反馈；你已经说“应该能到”，但尚未确认交通；另有一项已验证的预算条件刚好卡在上限。

请按自己的直觉操作，并持续说出你看到什么、理解什么、哪里犹豫，以及你期待系统做什么。没有正确答案；测试的是流程，不是你的能力。

## 5. 任务与观察点

| 编号 | 给参与者的任务 | 主要观察 | 完成信号 |
|---|---|---|---|
| T1 | 不点击任何内容，先说明当前有哪几类信息，以及你现在能处理什么。 | 是否区分本人待办、他人待办、边界风险。 | 说明“我需核实”“一人待回复”“风险仅供知情”。 |
| T2 | 找到并处理你自己的交通条件。若暂时无法确认，请选择最符合你的做法。 | 私人页面发现、本人确认边界、“更多时间”理解。 | 找到 My details；不会替他人确认；能说明预计时间不自动改变状态。 |
| T3 | 进入 Options，比较 C、A、B，并说明表格每一列代表什么、下一步是谁做。 | C/A/B 列头、个人与他人状态、候选描述。 | 读出 C/A/B；能说出“现在由我处理”。 |
| T4 | 假设你已核实交通可行。请把活动推进到正式发布。 | 暂定与发布的区分、发布复选框、Toast 干扰。 | 暂定后进入发布检查，勾选确认并发布。 |
| T5 | 在已发布结果里，确认收到；然后假设你想调整细节或重新比较。请任选一个处理。 | 已发布版本保留、问题回流路径、结果页视觉层级。 | 提出问题后能找到协调页面或仍可查看版本。 |
| T6（手机组） | 打开并关闭导航；进入 Options 后回到 Now。 | 抽屉的可发现性、遮罩、关闭行为。 | 使用汉堡按钮或 Esc/遮罩关闭；不迷失当前页面。 |

若参与者停滞约 45 秒，可重复任务原话一次；仍无法继续时记录为未完成，再由主持人推进至下一任务。不要解释术语或教操作。

## 6. 主持与回访重点

主持时只问开放问题：

- “你现在认为下一步是谁做？”
- “你认为别人会看到什么？”
- “这个状态对你意味着什么？”
- “你为什么会点这里？”

结束后追问：

1. 哪个状态最清楚，哪个最容易混淆？
2. 你是否在任何时刻觉得提示、Toast 或弹窗挡住了操作？
3. Options 页是否足以支持比较？哪些信息重复、缺失或难读？
4. 发布与发布后协调的区别是否清楚？
5. 你是否相信自己的路线、预算和原因不会被其他成员看到？为什么？

## 7. 成功标准与停止条件

| 指标 | 通过标准 |
|---|---|
| T1 状态与责任识别 | 至少 4/5 可区分本人待办、他人待办与边界风险。 |
| T2 私人条件边界 | 至少 4/5 知道只有本人可确认；无 2 人以上认为提醒可改变他人状态。 |
| T3 比较可读性 | 至少 4/5 正确理解 C/A/B 列头和下一步责任。 |
| T4 发布闭环 | 至少 4/5 无主持解释完成暂定与正式发布。 |
| T5 版本保留 | 至少 4/5 正确说明提出问题不会删除已发布版本。 |
| T6 手机导航 | 手机组 3/3 可发现并关闭抽屉；不出现阻塞性迷失。 |
| 视觉干扰 | 不出现 2 人以上报告 Toast、抽屉或弹窗遮挡关键操作。 |

若同一种安全关键误解在 2 人或以上出现（可替他人确认、私人原因会公开、发布会无痕撤销），暂停进入开发范围定义，先修订原型或信息架构。

## 8. 输出

- 每位参与者一份匿名原始记录；
- 任务完成矩阵、问题严重度表与关键原话；
- 高保真测试综合结论；
- MVP 开发范围、非功能性隐私要求与下一版修订清单。
