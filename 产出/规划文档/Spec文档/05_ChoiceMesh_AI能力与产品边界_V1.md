## 1. AI 产品架构原则

ChoiceMesh 采用混合架构：

```text
用户自然语言
→ AI 结构化建议
→ 用户确认
→ 确定性约束与排序引擎
→ 结构化计算结果
→ AI 取舍解释
→ 一致性检查
→ 成员反馈与最终确认
```

核心原则是：

> AI 负责处理语言的不确定性，规则引擎负责处理决策的确定性。

## 2. AI 能力清单

### A1：偏好与约束提取

输入：成员自然语言。  
输出：符合固定 Schema 的结构化建议。

示例：

```json
{
  "time": {
    "type": "hard",
    "available": ["Saturday 14:00-18:00"]
  },
  "budget": {
    "type": "soft",
    "max": 40,
    "currency": "AUD"
  },
  "travel": {
    "type": "soft",
    "max_minutes": 45
  },
  "clarifications": []
}
```

AI 不得：

- 自动保存未确认结果；
- 把“最好”“尽量”识别成硬性约束；
- 为模糊数字自行补全；
- 从成员身份推断预算、健康或出行能力。

### A2：澄清问题生成

当输入缺少可计算信息时，AI 生成最多两个针对性问题。

例如：

- “不想太贵”需要补充最高预算；
- “周六都行”需要确认最早和最晚时间；
- “不要太远”需要补充区域或最长通勤时间。

AI 不应重复询问已经结构化的信息。

### A3：推荐解释

输入只允许使用规则引擎生成的结构化结果：

- 可行性；
- 偏好命中；
- 最低和平均满意度；
- 主要取舍；
- 保留意见人数。

AI 只进行表达，不重新计算排名。

### A4：反馈总结

AI 将成员反馈归纳为：

- 新出现的硬性限制；
- 可调整的软性偏好；
- 候选方案信息问题；
- 无法通过当前候选解决的冲突。

总结结果必须保留与原始反馈的映射，供发起人检查。

### A5：行动摘要

在全员确认后，将最终候选方案中的已知字段整理为行动摘要。不得补充候选方案中不存在的地址、价格、预订状态或交通信息。

## 3. 规则引擎职责

- Schema 校验；
- 时间区间比较；
- 预算上限比较；
- 地点或通勤阈值比较；
- 活动条件匹配；
- 硬性约束过滤；
- 软性偏好计分；
- 最低成员满意度计算；
- 稳定排序；
- 无解检测；
- 最终确认状态。

## 4. 人类控制点

| 阶段 | 人类控制 |
|---|---|
| 自然语言提取 | 成员确认或修改 |
| 候选方案信息 | 发起人提供和校验 |
| 推荐结果 | 全体成员查看依据 |
| 反馈总结 | 发起人检查后发起修订 |
| 最终决定 | 每位成员独立确认 |
| 外部行动 | 用户自行复制、预订或联系 |

## 5. 产品边界

系统不会：

- 保证方案绝对公平；
- 判断成员的真实意图；
- 代替成员谈判；
- 自动说服持反对意见的成员；
- 操作私人日历、支付或预订；
- 生成不存在的地点信息；
- 将多数偏好包装成“全体共识”；
- 在有成员未确认时宣布完成。

## 6. 公平性设计

### 默认规则

- 成员权重相同；
- 硬性约束不参与加权；
- 排序同时展示最低个人满意度与平均满意度；
- 不只优化总分；
- 结果页面显示仍有保留意见的人数。

### 需要研究的问题

- 用户是否理解最低满意度指标？
- 是否应允许群体选择“效率优先”或“均衡优先”？
- 什么情况下硬性限制可能被滥用？
- 隐藏个人原因是否会降低解释充分性？

MVP 不提供可自定义权重，以避免未验证的复杂性。

## 7. 隐私与安全

- 自由文本在进入模型前尽量去除不必要个人信息；
- 不要求真实姓名、精确住址或私人日历；
- 推荐页默认只展示聚合结果；
- 系统 Prompt 明确忽略用户要求改变规则或泄露他人输入的指令；
- AI 输出必须通过 Schema 和一致性检查；
- 日志保存模型版本、错误类型和匿名 ID，不保存 API 密钥；
- 公开 Demo 使用合成数据。

## 8. 降级策略

### AI 解析失败

切换到手动结构化表单。

### AI 解释失败

展示规则引擎生成的模板化说明。

### 规则计算失败

不生成推荐，提示稍后重试并保留输入。

### 一致性检查失败

丢弃 AI 文本，回退到模板解释，同时记录 S1 错误。

## 9. 发布门槛

以下任何一项未达到时，不公开为可用 MVP：

- 规则引擎硬性约束测试未达到 100%；
- AI 可能绕过用户确认写入结构化结果；
- 解释可能改变排序或新增事实；
- 无解状态被包装成有效推荐；
- 隐私范围没有明确说明；
- 无法追踪 Prompt、模型和规则版本。
