# ChoiceMesh 成功指标与评测框架 V2

| 字段 | 内容 |
| --- | --- |
| 版本 | V2.0 |
| 更新日期 | 2026-08-24 |
| 状态 | 当前指标字典 |
| 项目性质 | 个人作品集与方法验证，不作为真实在线服务运营 |
| 产品契约 | 围绕一个当前提案协调；AI 只生成本人可见、可编辑、待确认的私密草稿 |

## 1. 指标要支持的判断

本框架不证明商业增长或生产可用性，只支持三个作品集判断：

1. ChoiceMesh 是否比群聊加投票更容易形成明确、可追溯的共同结果；
2. 成员是否理解私密输入、本人确认、提案变更和正式发布之间的边界；
3. AI 私密草稿是否减少手动整理成本，同时没有制造错误确认或虚构约束。

不再评测 AI 推荐活动、候选排序、推荐解释或“最优方案”。这些属于 V1 历史方向。

## 2. 证据状态标签

所有展示材料必须使用以下标签，避免把计划或 PoC 写成已验证结果：

| 标签 | 含义 |
| --- | --- |
| 已测量 | 已有任务记录、日志或评测报告，可追溯到样本与日期 |
| 方向性发现 | 小样本观察，用于发现问题，不代表总体比例 |
| 技术 PoC | 代码或测试证明机制可实现，不代表生产安全或稳定性 |
| 待验证假设 | 尚未获得真实结果，不得写成产品成效 |

## 3. 三个主结果指标

### 3.1 正式决定完成率

- **定义**：在统一任务时限内形成显式已发布结果的小组数 ÷ 开始任务的小组数。
- **成功事件**：`published`。
- **分母事件**：`room_created`，且小组实际开始任务。
- **报告方式**：个人项目样本较小时同时报告人数和分数，例如 `4/5 组`，不只报告百分比。
- **主要风险**：完成不等于所有成员满意，必须与隐私和误确认护栏一起解释。

### 3.2 建房到发布耗时

- **定义**：同一房间首次 `published` 时间减去 `room_created` 时间。
- **报告方式**：中位数、最小值、最大值，并说明是否包含主持人提示。
- **对照方式**：与完成相同任务的“群聊 + 投票”流程比较；小样本只报告方向，不做显著性结论。
- **主要风险**：任务熟悉度和组员响应速度会影响结果，应交换两种流程的测试顺序。

### 3.3 协调返工次数

- **定义**：因误读、遗漏、沉默被误当确认或提案变化而需要撤回、澄清、重新提交或重新确认的次数。
- **记录单位**：每个房间的观察计数，并保留原因分类。
- **原因分类**：`misread_reply`、`missing_response`、`proposal_changed`、`privacy_concern`、`unclear_owner`、`other`。
- **主要风险**：正常的提案变化不一定是失败；只有由沟通问题造成的额外循环才计为返工。

## 4. 驱动指标

驱动指标用于解释主结果，不作为独立成功故事：

| 指标 | 定义 | 对应事件 |
| --- | --- | --- |
| 邀请加入率 | 打开邀请并进入房间的人数 ÷ 收到邀请的人数 | `invite_joined` |
| 私密详情确认率 | 完成本人确认的成员数 ÷ 已加入成员数 | `details_confirmed` |
| AI 草稿编辑率 | 确认前修改过 AI 草稿的成员数 ÷ 生成草稿的成员数 | `draft_edited` / `details_confirmed` |
| 提案变更次数 | 正式发布前提出的共享提案变更数 | `proposal_changed` |
| 重新确认完成率 | 提案变化后再次确认的成员数 ÷ 被要求重新确认的成员数 | `details_reconfirmed` |

## 5. 用户信任与隐私护栏

| 护栏 | 记录方式 | 解释规则 |
| --- | --- | --- |
| “我的隐私与约束被尊重”评分 | 任务后 1–7 分量表，并记录原因 | 报告分布和原话，不把小样本均值外推 |
| 未授权私人信息可见事件 | 测试观察与双账号权限检查 | 目标为 0；任何一次都单独报告 |
| 错误确认事件 | AI 或界面把犹豫、沉默或提醒变成已确认 | 目标为 0；属于 S0 证据阻断项 |
| 无法人工继续的 AI 故障 | 超时、失败或无效输出后不能完成手动确认 | 目标为 0；必须保留人工路径 |

## 6. AI 私密解析指标

AI 指标只评价“把本人话语整理成待确认草稿”，不评价推荐或群体决策：

| 指标 | 分母 | 说明 |
| --- | --- | --- |
| Schema valid rate | 全部模型调用 | 返回值满足完整字段与类型契约 |
| Attendance accuracy | 有有效人工标签的样本 | 必须按明确肯定、犹豫、明确否定、未说明分层 |
| Over-claim rate | 标签不是 `attending` 的样本 | 被模型错误返回为 `attending` 的比例；S0 护栏 |
| Travel invention rate | 未陈述通勤数字的样本 | 模型虚构通勤数字的比例；S0 护栏 |
| Budget invention rate | 未陈述预算数字的样本 | 模型虚构预算数字的比例；S0 护栏 |
| Draft edit rate | 用户看到有效 AI 草稿的次数 | 作为可用性诊断，不等同于模型准确率 |
| Median / P95 latency | 成功与失败调用分别统计 | 小样本报告原始分布，不只给单点值 |

当前 `parse-details-golden-v1` 包含 200 条合成、单标注者仲裁样本，是项目级 Golden 回归集。它比首轮 37 条覆盖更广，但仍不能作为生产 benchmark。每次修改提示词、模型、标签或输出校验后，必须固定运行同一版本并保存日期化报告。

## 7. 方向性对照测试

- **建议规模**：先 3–5 组试运行，再视招募情况扩展到 5–8 组完整测试；每组 3–6 人。
- **对照条件**：ChoiceMesh 与“群聊 + 投票”完成难度相近的协调任务。
- **顺序控制**：交替两种工具的先后顺序，减少学习效应。
- **记录内容**：完成状态、耗时、返工、主持人提示、隐私评分、关键观察与访谈原话。
- **解释边界**：用于形成作品集方向性证据，不宣称统计显著性、市场验证或留存提升。

## 8. 不建设的生产指标

由于项目不计划真实运营，本阶段不建设生产级 DAU/MAU、付费转化、订阅收入、SLA、告警轮值或长期留存看板。可以保留首发场景、邀请转化和复用的假设，但必须标记为“待验证假设”。

## 9. 最小证据包

作品集最终至少展示：

1. 一页 V2 指标字典；
2. 一次群聊对照任务的记录与方向性结论；
3. 两个提示词版本的固定 AI 回归对比；
4. 一次 AI 故障降级验证；
5. 一次双账号隐私边界技术 PoC；
6. 已验证、方向性发现、技术 PoC 和待验证假设的清晰区分。
