## 1. 用户故事与验收

### US-01 创建共同起点

作为创建者，我想填写一个完整的活动提案和参与规则，以便群体围绕同一对象开始讨论。

**验收：** 未填写地点/区域、预计费用、时间或活动名称时，不能创建可评估房间；创建后生成邀请码。

### US-02 通过邀请码加入

作为受邀成员，我想登录后输入邀请码加入房间，以便我的私密信息能和身份可靠关联。

**验收：** 受邀成员加入后直接进入 Now；无效邀请码不创建成员关系；共同页面不显示其他成员身份。

### US-03 用自己的话表达条件

作为成员，我不想填写冗长表单，只想说一句话，让系统先帮我整理。

**验收：** 支持文本输入与语音转写入口；AI 仅生成私密草稿；成员能编辑、保留待核实、确认参加或确认无法参加；AI 草稿不会自动确认。

### US-04 了解下一步责任

作为成员，我想知道当前是等待他人回复、等待我本人核实，还是只存在需要知情的风险。

**验收：** 共同页面清楚区分 `no_response`、`needs_verification`、`confirmed`、`unavailable` 与 `boundary_risk`；提醒不改变状态。

### US-05 共同调整提案

作为成员，我想提出对活动时间、地点或费用的调整，但不希望任何人单方面覆盖现有决定。

**验收：** 提议保存后为待审；提议者可在获得支持前撤回；必须得到另一位成员支持才会成为当前提案；支持一项时关闭同房间其他待审项；受影响的私密条件重新进入待确认；页面明确说明当前由待审提案、本人确认还是参与人数阻止发布。

### US-06 正式发布

作为已确认的成员，我想在条件满足时发布正式结果，而不是把“暂时看起来可行”误解为决定。

**验收：** Publish 页面对已确认成员可见；按钮按照 V2 发布门槛禁用/解锁；发布需显式复选确认；发布后通知全体成员。

### US-07 保留版本处理问题

作为成员，我想在发布后提出细节问题或替代提案，但不希望既有结果被静默抹掉。

**验收：** 问题开启新协调轮次；旧版本仍可查看；新发布只能追加新版本。

## 2. 非功能需求

- 私密原文、路线、精确预算与原因仅本人及授权服务端可访问；
- 所有发布和提案支持操作均可审计；
- 共同页面只从服务端获取匿名聚合；
- 服务端在写入发布版本时重新验证所有门槛，前端按钮状态不能作为唯一依据；
- DeepSeek API 密钥只在服务端环境变量中存在，永不发送给浏览器。

## 3. 不纳入 V2 的需求

- 自动活动推荐、地点检索或路线规划；
- 基于私人信息的成员排序；
- 自动催促、自动拒绝、自动发布；
- 预订、支付与日历同步。
