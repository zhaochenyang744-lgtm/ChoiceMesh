# ChoiceMesh 成功指标与评测框架

| 字段 | 内容 |
|---|---|
| 文档版本 | V1.0 |
| 更新日期 | 2026-07-28 |
| 当前状态 | 待建立基线 |
| 评测对象 | 用户结果、规则引擎、AI 能力、系统质量 |

## 1. 指标原则

- 不以“生成次数”代替用户价值；
- 不只测平均满意度，也观察最低个人满意度和被忽略的硬性约束；
- 将确定性计算与 AI 生成分别评测；
- 所有目标值都是发布门槛，不是已取得的结果；
- 公开作品集中必须区分“目标”“基线”和“实测结果”。

## 2. 北极星结果

### 合格共同决策完成率

定义：

> 在限定时间内完成全员输入、生成可解释推荐、经过成员确认并形成最终行动计划的房间，占进入计算阶段房间的比例。

“合格”还必须满足：

- 没有违反成员硬性约束；
- 所有确认均由成员本人完成；
- 推荐理由与计算结果一致；
- 最终摘要信息完整。

MVP 用户测试目标：`≥ 70%`。

## 3. 用户结果指标

| 指标 | 计算方式 | MVP 目标 |
|---|---|---|
| 决策任务完成率 | 完成最终确认的测试组 / 开始测试的测试组 | ≥ 80% |
| 中位决策时间 | 从全部输入完成到形成推荐的时间 | ≤ 5 分钟 |
| 输入完成率 | 完成偏好提交的受邀成员 / 加入成员 | ≥ 85% |
| 推荐理解正确率 | 能正确解释推荐依据的成员 / 被测试成员 | ≥ 80% |
| 推荐可接受率 | 对至少一个推荐选择“接受/有保留”的成员比例 | ≥ 80% |
| 条件遗漏率 | 测试后发现未被系统捕获的重要条件 / 重要条件总数 | ≤ 10% |
| 结果公平感 | 5 分制问卷中“我的必要条件被考虑”平均得分 | ≥ 4.0 |

若条件允许，应与“群聊 + 普通投票”基线任务比较：

- 完成时间；
- 追问次数；
- 被遗漏的硬性条件数；
- 对最终结果的理解与接受度。

## 4. 确定性计算评测

规则引擎不依赖主观评分，发布前必须达到：

| 能力 | 门槛 |
|---|---|
| 硬性约束过滤准确率 | 100% |
| 无解情境识别准确率 | 100% |
| 相同输入结果一致性 | 100% |
| 排序规则单元测试通过率 | 100% |
| 成员等权规则一致性 | 100% |
| 推荐中出现不可行方案 | 0 |

任何硬性约束漏检都是发布阻断问题。

## 5. AI 能力评测

### 5.1 自然语言结构化

评测字段：

- 日期与时间；
- 最高预算；
- 地点或通勤限制；
- 活动偏好；
- 必要条件；
- 约束强度；
- 需要澄清的模糊表达。

门槛：

| 指标 | MVP 目标 |
|---|---|
| 字段级 F1 | ≥ 0.90 |
| 硬性约束召回率 | ≥ 0.98 |
| 约束强度识别准确率 | ≥ 0.95 |
| 应澄清表达识别率 | ≥ 0.90 |
| 错误结果未经用户确认直接保存 | 0 |

### 5.2 推荐解释

人工评分维度：

- 与计算结果一致；
- 没有新增不存在的事实；
- 清楚说明共同点；
- 清楚说明取舍；
- 不暗示 AI 已替群体决定；
- 语言简洁。

门槛：

| 指标 | MVP 目标 |
|---|---|
| 计算一致性 | ≥ 95% |
| 关键数字准确率 | 100% |
| 无依据事实率 | 0% |
| 取舍说明完整率 | ≥ 90% |
| 人工可读性评分 | ≥ 4/5 |

### 5.3 反馈总结

- 不遗漏“不可接受”反馈；
- 不把一般意见升级为硬性限制；
- 不改变反馈者的立场；
- 能将可执行调整与不可调和冲突分开。

## 6. 评测集设计

### 6.1 初始规模

- 结构化提取：60 条；
- 规则计算：40 个房间；
- 解释生成：30 个房间；
- 无解与边界：20 个房间；
- 回归测试：每次发现真实错误后补充样例。

### 6.2 情境分布

评测集至少覆盖：

- 所有人偏好一致；
- 只有一个可行方案；
- 多个方案分数接近；
- 时间冲突；
- 预算冲突；
- 地点冲突；
- 多重硬性约束；
- 模糊自然语言；
- 中英文混合输入；
- 否定表达；
- 所有候选都不可行；
- 个别成员软性偏好明显不同；
- 极端值和缺失字段；
- 带有试图改变系统规则的输入。

### 6.3 标注

每个样例保存：

- 原始输入；
- 人工结构化标准答案；
- 预期可行候选；
- 预期排序依据；
- 必须出现的解释点；
- 禁止出现的结论；
- 错误严重等级。

## 7. 失败分类

| 等级 | 示例 | 处理 |
|---|---|---|
| S0 | 违反硬性约束、泄露成员隐私、替成员确认 | 阻断发布 |
| S1 | 推荐排序错误、无解判断错误、解释与计算冲突 | 修复后才能发布 |
| S2 | 遗漏软性偏好、澄清不足、理由不完整 | 进入当前迭代 |
| S3 | 文案冗长、轻微格式问题 | 排入后续优化 |

## 8. 运行质量与成本

| 指标 | MVP 目标 |
|---|---|
| 规则计算 P95 | < 500 ms |
| AI 解析 P95 | < 5 秒 |
| 推荐解释 P95 | < 10 秒 |
| AI 调用失败后的规则结果可用率 | 100% |
| 单个完整房间 AI 成本 | 建立基线后再定门槛 |

## 9. 版本对比

每次修改 Prompt、模型或排序逻辑时保存：

- 版本号；
- 变更假设；
- 固定评测结果；
- 成本和延迟；
- 新增失败；
- 是否达到发布门槛；
- 保留或回退决策。

不得只展示“最好的一次”结果。
