# ChoiceMesh MVP 产品与流程规格 V2

| 字段 | 内容 |
| --- | --- |
| 版本 | V2.0 |
| 更新日期 | 2026-08-11 |
| 状态 | 当前验收依据 |

## 1. 核心对象

一个房间始终有且仅有一个 `current proposal`。它必须含有：活动名称、开始/结束时间、地点或区域、预计费用。

任何不完整提案只能保存为草稿或待补全，不能被计算为可发布方案。

## 2. 主流程

```text
创建房间并填写当前提案
  → 生成邀请码并邀请成员
  → 成员登录/验证身份后输入邀请码
  → Now：查看当前提案与匿名进度
  → My details：文字或语音转写 → AI 私密草稿 → 本人确认
  → 群体满足参与规则且当前提案可行
  → Publish：任一已确认成员进行发布检查与显式确认
  → 发布版本并通知成员
  → 后续问题进入新的协调轮次，旧版本保留
```

## 3. 页面职责

| 页面 | 解决的问题 | 不做什么 |
| --- | --- | --- |
| New room | 写下共同起点与参与规则 | 不替群体选择活动 |
| Join room | 输入邀请码并加入房间 | 不读取他人私密条件 |
| Now | 当前提案、匿名进度、下一步 | 不公开谁未回复或其原因 |
| My details | 本人表达、编辑并确认私密条件 | 不让任何人代替本人确认 |
| Proposal changes | 查看当前提案；提出或支持变更 | 不把保存的变更立即替换当前提案 |
| Publish | 检查发布门槛并正式发布 | 不把暂存或沉默当作发布 |
| Result / coordination | 查看已发布版本并开启下一轮 | 不覆盖既有版本 |

## 4. 参与规则

V2 只支持两种规则：

1. **达到最低确认人数即可继续**：创建者设置最低人数；人数满足但仍有人未确认时，已确认成员必须显式同意按当前人数继续。
2. **所有受邀成员确认**：任一未回复、待核实或无法参加都会阻止发布。

“关键成员必须确认”是历史探索，不属于当前 MVP。

## 5. 成员私密条件

- 每位成员输入一句话或通过语音转写输入；
- AI 只输出私密、可编辑的结构化草稿；
- 成员确认前，草稿不能改变共同进度或提案可行性；
- 共同页面仅展示匿名状态，例如“1 项待本人核实”“存在已验证边界风险”；
- 提醒只发送通知，不能改变对方状态。

## 6. 变更提案

“Adjust proposal”是对共同提案的操作，不是修改其他成员的个人条件。

1. 任一成员可以提交细节调整或替代提案；
2. 提议初始状态为 `pending_review`，当前提案保持不变；
3. 至少一位非提议成员明确支持后，服务端原子地使其成为当前提案；
4. 提议者可以在获得支持前撤回自己的待审提案；
5. 支持其中一项时，同一房间其余待审提案原子转为 `withdrawn`，避免旧提案永久阻塞发布；
6. 受时间、地点或费用变更影响的成员必须重新确认自己的条件；
7. 重新确认完成前，发布被阻止。

## 7. Publish 的访问与发布门槛

任何已确认自身条件的成员都可以打开 Publish 页面。页面可见不等于可以发布。

发布按钮仅在以下条件全部满足时解锁：

- 当前提案信息完整；
- 没有待审提案覆盖当前提案；
- 提案不存在硬冲突；
- 参与规则已满足，必要时已有继续决定；
- 受影响成员已完成重新确认；
- 发布者主动勾选“这将成为正式结果并通知成员”。

边界风险已验证但没有余量；它不会自动阻止发布，必须保留在结果中。

## 8. 发布后

- 每次发布写入新的不可变版本；
- “调整细节”与“重新比较/提出替代提案”只创建新的协调轮次；
- 已发布版本持续可读，不因后续问题撤销、覆盖或消失。
