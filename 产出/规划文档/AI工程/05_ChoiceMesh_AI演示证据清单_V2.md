这份清单回答的不是“能不能正式上线”，而是“展示时哪些能力有证据、哪些仍是设计或技术 PoC”。

## 1. 已实现并可演示

- AI 只解析单个成员主动提交的文本，不推荐活动、不决定出席、不改变共享状态。
- 模型输出先经过结构校验，再作为本人可编辑的私密草稿呈现。
- 成员必须明确确认；AI 草稿不会自动成为群体结论。
- API Key 位于服务端；代码日志只记录版本、结果类型和延迟，不记录完整原文。
- 无 API Key、超时、上游错误、无效 JSON 或 Schema 失败时，用户可重试或改用手动填写。

## 3. 隐私与后端证据分级

| 证据 | 可以表述 | 不可以表述 |

| UI 原型 | 设计了私密确认和匿名群体状态 | 已保证真实数据隐私 |

## 4. 明确不做的生产建设

- 多实例限流、成本告警、SLA 和 24/7 运维。
- 大规模真实用户数据采集与长期留存分析。
- 支付、订阅、增长系统和商业化验证。
- 对第三方模型供应商做完整法务、合规与采购审查。

## 5. 展示时的诚实结论

推荐表述：ChoiceMesh 用“AI 私密解析 + 人工确认 + 确定性群体规则”验证了一套克制的 AI 协作机制，并通过固定回归集和失败降级测试展示其边界。

当前 `parse-details-v5` 仍有 1 条 over-claim，未通过零 over-claim 门槛。演示时应把它作为评测发现与下一步修复项，而不是宣称模型已经放行。

避免表述：产品已上线、模型已达到生产水平、RLS 证明了端到端隐私、200 条合成样例证明真实用户效果。
