## 1. 信息架构

```text
登录
├─ 创建房间
│  ├─ 活动与时间
│  ├─ 当前提案（地点/费用）
│  ├─ 参与规则
│  └─ 邀请码
└─ 加入房间
   └─ 输入邀请码

房间工作区
├─ Now
│  ├─ 当前提案
│  ├─ 匿名进度与下一步
│  └─ 已验证边界风险
├─ My details（仅本人可见）
│  ├─ 文字/语音转写输入
│  ├─ AI 私密草稿
│  └─ 本人确认、待核实或无法参加
├─ Proposal changes
│  ├─ 当前提案
│  ├─ 待审变更
│  └─ 支持变更
├─ Publish
│  └─ 发布检查与显式确认
└─ Result / coordination
   ├─ 已发布版本
   └─ 新协调轮次
```

## 2. 三个体验原则

1. **个人输入私密，群体状态匿名。** 成员能确认自己的条件，不需要向群体说明原因。
2. **提议不是决定。** 创建时的提案、待审变更、可发布提案和已发布结果具有不同状态。
3. **动作不替人。** 提醒不等于回复，AI 草稿不等于确认，满足人数不等于发布。

## 3. 核心流转

| 触发 | 可见结果 | 不会发生的事 |
| --- | --- | --- |
| 成员发送一句话/语音 | 私密 AI 草稿 | 共同状态不会自动变确认 |
| 成员确认草稿 | 匿名确认或待核实状态 | 原文不会共享 |
| 提交提案变更 | 待审变更 | 当前提案不会立即替换 |
| 另一成员支持变更 | 新提案成为当前；受影响者需重确认 | 不会代替受影响者确认 |
| 发布 | 新的正式版本与通知 | 旧版本不会被覆盖 |
| 发布后提出问题 | 新协调轮次 | 已发布版本不会撤销 |
