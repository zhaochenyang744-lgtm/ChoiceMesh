## 1. 视觉论点

ChoiceMesh 应像一张**冷静、可信的共同决策画布**，而不是投票游戏或群聊替代品。界面优先让人看清：现在谁需要做什么、哪些信息已确认、哪些风险只需知情。私密信息不以“被隐藏的内容”出现，而以匿名状态和可解释的边界呈现。

设计关键词：**沉稳、可核实、不过度催促、共同但不越界**。

## 2. 色彩与状态语义

| 令牌 | 色值 | 语义 | 典型使用 |
|---|---:|---|---|
| `ink` | `#14211C` | 主要文字 | 标题、关键信息 |
| `canvas` | `#F4F6F2` | 工作区底色 | 页面背景 |
| `surface` | `#FFFFFF` | 内容容器 | 卡片、表格、输入面板 |
| `green` | `#176244` | 已确认 / 明确推进 | 主操作、已确认、发布 |
| `green-pale` | `#E3F2E9` | 确认背景 | 成功状态 |
| `waiting` | `#6553A8` | 等待第一条反馈 | “回”图标、等待标签 |
| `waiting-pale` | `#EFEAFD` | 等待背景 | 等待卡片 |
| `verify` | `#26679F` | 已回复、待本人核实 | “核”图标、本人动作 |
| `verify-pale` | `#E8F1FB` | 核实背景 | 核实卡片 |
| `risk` | `#9C5A16` | 已验证但无余量 | 虚线风险标签、知情提示 |
| `risk-pale` | `#FFF6E7` | 风险背景 | 非待办风险提示 |
| `blocked` | `#AA463E` | 已确认硬冲突 / 无法参加 | 冲突、拒绝状态 |
| `blocked-pale` | `#FBECE9` | 冲突背景 | 硬冲突标签 |

状态不允许只依赖颜色。必须同时使用：

- 文本标签；
- 有语义的单字状态标记（回、核、险、缺、确）；
- 下一步行动或“不需要行动”的解释。

`等待回复` 与 `待本人核实` 是不同工作类型：前者用紫色“回”和“由对方提交”，后者用蓝色“核”和“由你验证”。`边界风险` 为琥珀色虚线，永远带“仅供知情 / 不阻止”的说明。

## 3. 字体、版式与组件基线

### 字体

- 使用系统无衬线栈：`ui-sans-serif, system-ui, -apple-system, "Segoe UI", sans-serif`；
- 全站只使用七档 token：`11 / 13 / 15 / 20 / 28 / 42 / clamp(28px, 3.2vw, 40px)`；
- 页面标题使用最后一档；正文 15 px，辅助信息 11–13 px；
- 不以全大写或颜色单独表达状态。

### 布局

- 桌面：220 px 深绿侧栏 + 74 px 顶栏 + 最大宽度 1080 px 的内容画布；
- 主内容使用 8 px 间距基线；常用卡片内边距 20–24 px，圆角 12–14 px；
- 顶部使用常驻步骤条：创建、现在、条件、方案、发布、结果。步骤条承担流程定位，页标题只负责点题；
- 两栏页面统一使用 `1.15fr / .85fr`；小于 800 px 时变为单栏，顶部导航与步骤条横向滚动；
- 任何私人字段编辑只能出现在“我的条件”私有页面，不能被缩进到共同卡片或悬浮提示中。

### 表面节奏约束

- 常规协调页面只使用白色 `surface`；
- 深色发布卡只用于“正式发布”的郑重确认；
- 浅绿结果 Hero 只用于已发布结果；
- 除以上三种表面外，不新增新的装饰性表面风格。

### 关键组件

| 组件 | 目标 | 高保真要求 |
|---|---|---|
| 行动卡 | 让成员立刻知道下一步 | 状态标记、责任主语、简短解释、唯一主动作；不得把风险混入行动计数。 |
| 知情提示 | 显示风险而不制造阻塞感 | 琥珀虚线、标题“只需知情”、说明“不需要催促”；不提供虚假的“解决风险”按钮。 |
| 状态标签 | 快速扫描 | 标签文本不可省略；等待 / 核实 / 风险有不同图标与颜色。 |
| 私有条件编辑器 | 让成员确认自己的事实 | 明确“仅你可见”；预计时间必须是可编辑输入，不是预置答案。 |
| 候选比较表 | 显示条件覆盖 | 只显示匿名聚合；风险在小群体自动降精度。 |
| 发布检查 | 制造有意义的确认摩擦 | 主复选框使用“我确认”，按钮在勾选前不可用；同时显示实际确认人数与成行门槛。 |

## 4. 动效与反馈

- 页面路由切换：150–200 ms 的淡入上移；减少动态偏好下关闭或降为即时切换；
- 状态更新：仅局部替换卡片、标签与行动说明，不用庆祝动画；
- 预计时间：点击“需要更多时间”后以内联展开输入，保存后回到待核实状态并显示本人的具体时间；
- 提醒：发送后按钮进入冷却状态，文本明确“不会替对方回复”；
- 发布后问题：优先显示“调整当前方案”，重新比较保持次级；两条路径都保留版本记录。

## 5. 无障碍与内容约束

- 正文与底色、状态文字与状态底色至少满足 WCAG AA 对比度；
- 焦点状态必须清晰可见，所有按钮可用键盘操作；
- 输入必须关联可见标签和辅助说明；动态消息使用 `aria-live`；
- 不用“某成员”“某人的预算”等可反推措辞替代匿名聚合；有效参与人数小于 4 时，风险只写“存在已验证风险”；
- 视觉稿需同时给出桌面与窄屏关键状态，不能只交付一个静态成功态。

## 6. 高保真验收清单

- [ ] 首屏 10 秒内可区分“等他人回复”与“我需要核实”；
- [ ] 风险可见，但不被视觉上误读为第三项待办；
- [ ] 私有条件页清楚说明当前身份、可见范围与本人操作边界；
- [ ] 预计确认时间可以自行输入，群体侧只看见其存在；
- [ ] 提醒显示已发送 / 冷却状态，不改变任何确认状态；
- [ ] 发布页同时呈现实际确认人数、最低门槛与保留风险；
- [ ] 发布后的默认恢复动作是“调整当前方案”。
